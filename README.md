# forQUIK-scalp — QLua-инструменты для FORTS

В репозитории два независимых скрипта для QUIK:

| Скрипт | Что делает | Документация |
|---|---|---|
| [`SCLP/sclp.lua`](SCLP/README.md) | **ручной** маркет-мейкинг горячими клавишами: ↑/↓ — пассивные заявки с отступом, тейк-профит, авто-перестановка, PANIC, метрики, восстановление после перезапуска | [SCLP/README.md](SCLP/README.md) |
| `scalp.lua` | **автоматический** скальпер: сам ищет моменты входа (сетапы), держит позицию и выходит | этот файл |

Не запускайте их на одном контракте одного счёта: встречные заявки дают кросс-сделки (отказ биржи и сбор за ошибочную транзакцию).

Общее для обоих: новые заявки уходят с условием «Только пассивная» (Book-or-Cancel). В фиксированном формате транзакции QUIK такого значения у `EXECUTION_CONDITION` нет (ARQA, 17.06.2026), поэтому используется **универсальный формат** с русскими названиями полей (переводятся в CP1251). Названия зависят от брокера: перед боем запустите `tools/probe_passive.lua` и при отказе перенесите поля из `.tri`-файла «Кармана транзакций» в `TX`. У вашего брокера отказ BoC приходит как `[GW][82]`.

## scalp.lua — автоматический скальпер

### Как устроен

Колбэки QUIK (`OnQuote`, `OnAllTrade`, `OnOrder`, `OnTrade`, `OnTransReply`) только кладут события в очередь. Основной цикл (`LOOP_MS = 1`) разбирает очередь, читает стакан и на каждом проходе:

1. обновляет сигналы (`book.lua`, `alpha.lua`): стакан без своих заявок, дисбаланс, OFI, выносы, справедливая цена, σ, режим рынка, VPIN;
2. ведёт открытые циклы (`cycle.lua`): вход → позиция → выход;
3. ищет новые входы по сетапам (`setups.lua`, `mm.lua`, `breakout.lua`) через фильтр отбора (`guard.lua`) и риск (`risk.lua`);
4. обслуживает заявки (`oms.lua`), статистику, окна, состояние.

Все инструменты — в одном скрипте; у каждого может быть опорный инструмент (`REF`) — только как фильтр.

### Сетапы

Режим каждого: `"live"` (реально при `MODE = "LIVE"`), `"paper"` (виртуально на живом стакане, эмулятор `paper.lua`), `"off"`.

| Сетап | Идея | Тип заявок |
|---|---|---|
| TIGHT | пара у рынка при дырке 0–2 тика по правилам объёмов, захват 1 тик; выключается сам, если комиссия больше ~0,4 тика | пассивные |
| PAIR | «тихая» дырка ≥ `PAIR_MIN_SPREAD` тиков (снятие, а не вынос; опорный стоит; дисбаланс и поток нейтральны): bid + ask внутрь спреда | пассивные |
| FADE | после большого выноса — против движения внутрь пустоты | пассивные |
| WALL | на тик впереди крупной стены (или айсберга) за пустотой | пассивные |
| MM | котировки Гэана–Леалля–Тапии / Авелланеды–Стойкова с перекосом от позиции | пассивные |
| MOMO, SQZ, NEWS | импульс по CVD, пробой канала Кельтнера, OCO-пробой перед событием | **тейкерские** |

Правило пары: если биржа отклонила одну ногу (стала бы тейкером), вторая снимается.

### Выход

`EXIT_MODE` (по умолчанию `"AS"`):

- `"AS"` — цена выхода по котировке A-S / GLT от суммарной позиции, стоп по волатильности `VOL_STOP_K · σ · √60`;
- `"HOLD"` — тейк висит до конца дня;
- `"PHASES"` — TP → DECAY → HOLD → BE → STOP по возрасту позиции (`MAX_HOLD_SEC`).

Поверх любого режима: **мягкий стоп** `SOFT_STOP_PCT` (0,3%) — выход пассивно самой близкой к рынку ценой; **жёсткий стоп** `HARD_STOP_PCT` (0,5%) — заявка IOC (`KILL_BALANCE`) по рынку. Тейкерские заявки робота — только жёсткий стоп и сетапы MOMO/SQZ/NEWS.

### Риск

- позиция — по худшему случаю (все стоящие заявки исполнятся), `MAX_POS` ≤ `HARD_MAX_POS`, плюс лимит по VaR от остатка дневного бюджета;
- дневной лимит убытка с учётом открытых позиций, просадка от пика дня (`DAY_DD_LIMIT_RUB`);
- паузы: после убытка, после серии убытков, при резком движении (`MOVE_PAUSE_*`, в процентах), после серии отказов;
- автоотключение сетапа, который значимо теряет за день (`guard.lua`);
- окна торговли `SESSIONS` / `SESSIONS_WEEKEND`; в последние минуты окна — только закрытие;
- больше `MAX_ERR_TX_PER_DAY` ошибочных транзакций — только закрытие;
- чужие активные заявки на контракте (`FOREIGN_ORDERS_BLOCK`) — по нему торгует только виртуально.

### Текущие настройки (`scalp_config.lua`)

- `MODE = "LIVE"`, счёт `SPBFUT17Y1j`, `HARD_MAX_POS = 50`, `DAILY_LOSS_LIMIT_RUB = 5000`;
- инструменты (`MAX_POS = 10` у каждого): BM за BR, GLDRUBF за GD, CNYRUBF за CR, IMOEXF за индексом IMOEX;
- у всех: TIGHT и PAIR — `live`; FADE, WALL, MM, MOMO, SQZ — `paper`;
- `EXIT_MODE = "AS"`, стопы 0,3% / 0,5%, `BROKER_FEE_RUB = 0` (комиссия брокера по текущему тарифу — 0).

Настройки перечитываются каждые 5 с, кроме `MODE`, `ACCOUNT`, `TX` и списка инструментов. Все параметры с пояснениями — `sc_lib/defaults.lua`; формулы — `docs/model.md`; исследование — `docs/research.md`.

### Перезапуск и команды

- `scalp_state.txt` — реальные циклы (позиция, цель, живые заявки) и итоги дня. После перезапуска в тот же день заявки подхватываются из таблицы заявок (`ADOPT_ORDERS`), исполнения за простой учитываются по остатку, позиции сверяются с брокером; не подхваченные свои заявки снимаются.
- Команды — слово в `scalp_cmd.txt` (читается раз в секунду): `pause`, `resume`, `flatten`, `cancel`, `show`.
- Копия `scalp_BR.lua` + `scalp_config_BR.lua` работает отдельно: свои журналы, состояние и диапазон TRANS_ID.

### Журналы

`scalp_ГГГГММДД.log` (сводка раз в минуту), `scalp_gaps_*.csv` (каждая дырка), `scalp_cycles_*.csv` (циклы), `scalp_fills_*.csv` (маркауты входов), `rec_scalp_*.csv` (запись стакана при `RECORD_MARKET`). Разбор: `python tools/scalp_study.py`. Окна QUIK: «Скальпер», «Скальпер: сетапы», «Скальпер: сделки».

## Тесты (Lua 5.3/5.4, без QUIK)

```
lua tools/test_scalp.lua         # автоскальпер, 154 проверки
lua SCLP/tools/test_sclp.lua     # SCLP, 98 проверок
```

Тесты проверяют механику (пассивность, лимиты, перезапуск, инварианты позиции), а не доходность: случайный рынок эмулятора информации о будущей цене не содержит.

## Ограничения

- Прибыльность автоскальпера не доказана: при реальной торговле итог был около нуля. Решать по маркаутам и доле прибыльных против безубыточной (`win% … vs break-even …` в журнале).
- Задержка QUIK и брокера — 60–250 мс; дырки короче недоступны.
- В одностороннем движении пассивный выход отстаёт; жёсткий стоп платит спред и сбор тейкера.
