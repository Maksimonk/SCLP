# SCLP — ручной маркет-мейкинг в QUIK горячими клавишами

Это отдельный скрипт для торговли руками. Нажимаете стрелку — уходит заявка **«Только пассивная»** (Book-or-Cancel биржи) с заданным отступом от стакана. Всё остальное делает скрипт:

- держит заявку на месте относительно рынка;
- ставит тейк-профит;
- следит за лимитами;
- считает P&L и маркауты;
- переживает перезапуск, не теряя заявок и открытых ног.


## Запуск

1. Скопируйте папку `SCLP` к QUIK целиком: `sclp.lua`, `sclp_config.lua`, `lib/`.
2. Счёт FORTS — `ACCOUNT` в `sclp_config.lua` (`SPBFUT17Y1j`). Комиссия брокера по текущему тарифу 0 (`FEES.SPBFUT.BROKER_RUB = 0`).
3. **Один раз перед боем** запустите `SCLP/tools/probe_passive.lua` в торговое время (инструмент — `DEFAULT_INSTRUMENT`). Он проверяет, что ваш QUIK принимает «Только пассивная» в универсальном формате. Названия полей те же, что в `TX`.
4. QUIK → Сервисы → Lua скрипты → `SCLP/sclp.lua` → Запустить.
5. Появится окно **SCLP**. **Горячие клавиши работают, только когда это окно в фокусе.** В QLua нет глобальных хоткеев: клавиши из окна стакана скрипт не видит.

После старта скрипт 3–5 с ждёт, пока QUIK догрузит таблицы. Затем сверяет своё состояние с биржей и показывает окно «восстановление после запуска». Пока идёт сверка, торговые клавиши не работают.

## Окно

Слева — настройки и состояние, справа — метрики.

Настройки меняются на ходу: **двойной клик** по строке (или Enter на выделенной), набрать значение, **Enter** — применить, **Esc** — отмена. Пока идёт ввод, торговые клавиши выключены. Значения проверяются:

| Поле | Проверка |
|---|---|
| тикер | существует, есть шаг цены, не истёк |
| объём | не меньше 1 |
| отступ | ±`OFFSET_MAX` |

Значения запоминаются.

Инструмент можно ввести так:

- `SPBFUT BRX6` — класс и код;
- `BRX6` — класс найдётся сам по `CLASS_PRIORITY`;
- `BR` — ближайший живой контракт.

Пока по текущему инструменту стоят заявки, сменить его нельзя. Если по нему открыта позиция, нужно ввести новый тикер дважды: она останется в файле, и SCLP её не сопровождает.

## Горячие клавиши

| Клавиша | Действие |
|---|---|
| **↑** | КУПИТЬ: пассивная покупка, цена = лучший бид − отступ |
| **↓** | ПРОДАТЬ: пассивная продажа, цена = лучший аск + отступ |
| ← / → | отступ −1 / +1 тик (не меньше 0; больше — дальше от рынка) |
| + / − (клавиши «=» и «−» справа от цифр, Shift не нужен; или + / − на цифровом блоке) | объём +1 / −1 |
| B / S | снять все покупки / все продажи |
| C или Esc | снять все заявки |
| F | закрыть позицию пассивно (самая агрессивная пассивная цена в момент нажатия) |
| H | пауза / продолжить |
| R / K | перестановка закрытия по F (не хуже безубытка) / перекос от позиции — вкл/выкл |
| T | **встречная после исполнения** (по умолчанию выкл., T или двойной клик — вкл/выкл): заявка по стрелке исполнилась → сама ставится встречная пассивная с общим отступом по текущему рынку (после покупки — продажа по аску + отступ, после продажи — покупка по биду − отступ), **но всегда не хуже своей цены исполнения ± max(отступ, 1) тик** с учётом комиссий; отключить эту защиту нельзя. Прибыль встречной считается против её собственной сделки (а не самой старой). Если биржа отклонила встречную (рынок сдвинулся), она ставится заново по новому стакану. **Если на стороне встречной уже стоит ваша заявка по стрелке** с ценой не хуже этой границы (вы котировали обе стороны), она и становится встречной — вторая заявка не добавляется, позиция не «перелетает» |
| **P, P** (за 2 с) или двойной клик по строке PANIC | **PANIC** |
| A, A | после расхождения позиции при старте — принять позицию QUIK |

Буквенные клавиши работают и в русской раскладке. Задержки между нажатиями нет: каждое нажатие стрелки — заявка (`KEY_COOLDOWN_MS = 0`). Осторожно: если **удерживать** стрелку, Windows повторяет нажатие ~30 раз в секунду, и каждое станет заявкой; защита — `KEY_COOLDOWN_MS = 150` в `sclp_config.lua`.

## Как считается цена

Отступ — сколько тиков **отойти от лучшей цены своей стороны вглубь стакана**, чтобы купить дешевле или продать дороже. Лучшая цена берётся такой, какой её показывает стакан QUIK (вместе с вашими заявками):

```
ПОКУПКА = лучший бид − отступ        ПРОДАЖА = лучший аск + отступ
отступ 0 — встать в лучшую цену; больше — глубже. Отрицательный отступ запрещён
```

Пример: бид 101.00, аск 101.02, отступ 2 → покупка 100.98, продажа 101.04.

Такая заявка всегда стоит в лучшей цене или глубже, поэтому сама по себе пассивна. Дополнительно цена ограничена: покупка ≤ аск − 1 и ниже своей продажи, продажа ≥ бид + 1 и выше своей покупки (на случай пересечённого стакана и кросс-сделки с собой).

Почему раньше «не всегда верно исполнялось»: прежняя формула (бид + отступ, внутрь спреда) упиралась в аск − 1. Например, при спреде 2 тика отступы 1, 2 и 3 давали одну и ту же цену, а лучшая цена считалась без ваших заявок и могла не совпадать с тем, что вы видите в стакане QUIK. Теперь цена всегда «бид − N» / «аск + N» от видимого стакана.

Пассивность защищена в три слоя:

1. **Проверка стакана** перед отправкой. Стакан перечитывается в момент нажатия.
2. **Признак биржи «Только пассивная» (Book-or-Cancel).** На FORTS (`SPBFUT`, `SPBOPT`) заявка уходит в универсальном формате с полем «Условие исполнения = Только пассивная». В фиксированном формате (`EXECUTION_CONDITION`) такого значения нет — ARQA подтвердила это 17.06.2026. Если стакан успел сдвинуться, биржа **отклоняет** заявку (у вашего брокера код `[GW][82]`). SCLP ничего не исполняет и пишет «Отказ биржи: заявка стала бы тейкерской». Первая принятая заявка проверяется по полю `passive_only_order`: если признак не дошёл до биржи, SCLP останавливает торговлю (HALT).
3. **Никакого запасного «обычного лимита».** Все заявки, кроме PANIC (вход по клавишам, тейк-профит, пассивное закрытие F), уходят только с «Только пассивная» — на любом классе. Если QUIK не принимает поля, SCLP останавливает торговлю (HALT), а не шлёт простую лимитку. Для фондового рынка проверьте поля `probe_passive.lua` и при необходимости задайте их в `TX_BY_CLASS = { TQBR = { ... } }`.

## PANIC — единственная тейкерская операция

PANIC делает три шага:

1. Снимает все заявки SCLP по инструменту. С `PANIC_KILL_SCOPE = "account"` — все заявки счёта по инструменту, включая ручные.
2. Ждёт подтверждений снятия (до 2 с), чтобы не получить кросс-сделку с собой.
3. Закрывает позицию заявками **IOC** (`KILL_BALANCE`) «по рынку»: продажа ставится по нижней границе цен биржи (`PRICEMIN`), покупка — по верхней (`PRICEMAX`). Биржа исполняет её по лучшим ценам стакана, лимит лишь разрешает любую цену; что не исполнилось сразу — снимается. Если границы неизвестны — лучшая встречная ± `PANIC_SLIP_TICKS`. Повтор — до 10 попыток.

**P&L считается по реальным сделкам, а не по цене заявки.** Цена в таблице заявок QUIK — это лимит (для PANIC — граница 65.00), а исполнение идёт по ценам сделок, часто по нескольким уровням. SCLP берёт цену и объём **из таблицы сделок QUIK** (OnTrade — это её строки; номер сделки защищает от двойного учёта) и считает среднюю цену исполнения заявки. Как только таблица заявок показывает исполнение, а сделка ещё не учтена, скрипт сразу и затем раз в секунду читает таблицу сделок. Предполагаемых цен нет: позиция меняется только по реальным сделкам. В журнале: `PANIC fill 2 @ avg 69.985 (limit 65.00, best at send 69.99, slippage 0.5 ticks)`; в `sclp_orders_*.csv` — колонка `avg_fill_price`.

Компромисс: закрытие стоит спреда, проскальзывания и тейкерского сбора. Поэтому PANIC требует явного действия (P дважды или двойной клик) и пишется в журнал. После PANIC торговля стоит на паузе (H — продолжить).

Объём фиксируется один раз в начале и уменьшается только своими исполнениями, поэтому запаздывающая таблица позиций не приведёт к перевороту. Через 3 с после PANIC позиция сверяется с брокером. Если там не ноль (ручные сделки), выводится предупреждение.

Мягкая альтернатива — **F**: закрыть пассивно.

## Риск и паузы

- **Лимита позиции нет** — позицию контролируете вы.
- **Лимит убытка дня.** Итог сессии (закрытые + открытые, за вычетом комиссий) ≤ −лимита → стоп. Если `AUTO_PANIC_ON_LOSS`, сразу PANIC. Стоп снимается, только если поднять лимит в окне.
- Ограничений на объём заявки и число заявок в минуту нет; остаётся предупреждение о высоком OTR.
- **Не открывать позицию:**
  - нет связи;
  - нет стакана;
  - торги приостановлены (параметры `STATUS` / `TRADINGSTATUS`);
  - окна клиринга и аукционов из `PAUSE_WINDOWS` (в начале окна стоящие заявки снимаются);
  - аномальный спред (> `SPREAD_WIDE_K` × средний).
- **Тейк-профит и закрытие** проходят и в этих случаях: они уменьшают риск.

## Перестановка — только у закрытия по F (R)

Заявки, выставленные стрелками, скрипт **не двигает никогда** — даже если они встречные к позиции: можно держать котировки с обеих сторон, как задумано. Тейк-профиты тоже не двигаются.

Двигается только пассивное закрытие, поставленное клавишей **F**, и только пока включено R:

- оно следует за рынком (самая агрессивная пассивная цена: бид + 1 / аск − 1);
- но только к ценам не хуже **безубытка** — средняя цена позиции плюс комиссии входа и выхода. Если рынок хуже безубытка, заявка остаётся на месте;
- перестановка: снять → дождаться подтверждения → поставить заново, не чаще раза в 300 мс.

После отказа биржи по BoC заявка не пересылается. Скрипт сам снимает заявки ещё в трёх случаях: PANIC; начало окна клиринга/аукциона (`CANCEL_ON_PAUSE`); тейк-профит, когда закрываемой позиции больше нет.

## Окно «SCLP: средние цены»

Открывается рядом с основным. По реальным ценам сделок (из таблицы сделок) за день:

| Строка | Что значит |
|---|---|
| Куплено, лотов / Средняя цена покупок | сколько куплено за день и по какой средней цене |
| Продано, лотов / Средняя цена продаж | то же по продажам |
| Позиция (открытые ноги) / Средняя цена позиции (FIFO) | что сейчас открыто и по какой средней цене входа |
| Безубыток закрытия | цена, не хуже которой нужно закрыть позицию, чтобы не уйти в минус с учётом комиссий |

Ширину столбцов QLua прочитать не умеет (нет такой функции), поэтому она задаётся в `sclp_config.lua`: `UI_COL_WIDTHS = { main = { 30, 44, 28, 30 }, avg = { 30, 24 }, report = { 160 } }` (в символах). Если окно закрыть, через секунду оно откроется снова (как и основное). Все окна SCLP запоминают положение и размер (`sclp_ui.lua`, сохраняется раз в 5 с и при остановке) и открываются там же.

Пример: купили 5 по 70.00, 70.01, 70.01, 70.02, 70.03 → «Куплено 5, средняя 70.0140».

## Метрики (правая половина окна) и журналы

| Метрика | Как читать |
|---|---|
| Реализ. P&L гросс / нетто | по закрытым частям (FIFO); нетто = минус комиссии входа и выхода |
| Нереализ. P&L | по середине стакана без своих заявок, минус комиссия входа и оценка комиссии выхода |
| ИТОГО / P&L в час / на сделку | итог сессии; «в час» — с начала сессии |
| Сделок / win rate / ср. выигрыш и проигрыш / profit factor | «сделка» — каждое уменьшение позиции. Безубыточный win rate = ср. проигрыш / (ср. выигрыш + ср. проигрыш) |
| Макс. просадка | от пика итога за день |
| Макс. позиция / экспозиция | экспозиция = \|позиция\| × цена × стоимость пункта, руб |
| Заявок: отпр/исп/снято/откл, fill ratio | fill ratio — доля заявок с исполнением |
| OTR | (заявки + снятия) / исполнения. Растёт от частых снятий; выше `OTR_WARN` — жёлтый |
| Отказы BoC / ошибочные tx | ошибочные (отказы, неудачные снятия) MOEX тарифицирует — держите около нуля |
| Клавиша → отправка, мс | время в очереди скрипта (обычно 1–16 мс: таймер Windows) |
| Отправка → ответ, мс | QUIK + брокер + биржа; обычно здесь основная задержка |
| Спред / сигма | сигма — волатильность середины, тиков/√с |
| Маркаут 1/5/30 с | сдвиг середины в вашу сторону после исполнения, тиков. **Отрицательный маркаут на 5–30 с = вас выбирают информированные (adverse selection)**: увеличьте отступ, включите перекос, не стойте одним на вершине |
| Тейкерских исполнений | должно быть 0 |

Про OTR. Правила MOEX о сборах за транзакционную активность могли меняться. По прежнему исследованию проекта, сбор за неэффективные транзакции на срочном рынке отменён с 2022 года, а за ошибочные остался. Точные правила проверьте у брокера.

Журналы лежат рядом со скриптом:

| Файл | Что внутри |
|---|---|
| `sclp_ГГГГММДД.log` | события |
| `sclp_fills_*.csv` | каждое исполнение: спред, сигма, задержки, P&L закрытия, комиссия, признак тейкера, маркауты 1/5/30 с |
| `sclp_orders_*.csv` | жизненный цикл каждой заявки: задержки, время жизни, отказ |
| `sclp_session_*.csv` | снимок метрик раз в минуту (кривая итога) |

## Перезапуск без потери заявок и ног

**Где хранится состояние.**

- `sclp_settings_<СЧЁТ>.lua`:
  - настройки окна и активный инструмент;
  - список инструментов с открытыми ногами;
  - счётчики сессии и стоп по убытку.
- `sclp_state_<СЧЁТ>_<КЛАСС>_<КОД>.lua`:
  - живые заявки: TRANS_ID, номер, сторона, цена, объём, исполнено, назначение (key / tp / flat / panic), время;
  - **открытые ноги** — несведённые исполнения FIFO: сторона, цена, остаток, номер сделки, время, TRANS_ID привязанного тейк-профита;
  - номера уже учтённых сделок;
  - метрики дня.

**Как пишется.** Сначала `.tmp`, затем прежний файл становится `.bak` (резервная копия), затем `.tmp` переименовывается в основной. При чтении пробуются основной файл, `.tmp`, `.bak`. Оборванный файл не разбирается как Lua, поэтому сбой посреди записи не даёт загрузить битое состояние. Файл грузится без доступа к глобальным функциям.

Запись идёт по событиям: заявка, ответ, исполнение, снятие, отказ, смена настроек. Не чаще одного раза за проход цикла и **после** отправки транзакции — задержку клавиши запись не увеличивает.

**Сверка при старте.** Источник правды — QUIK, файл только подсказка.

1. Заявки из файла, которые ещё активны в таблице заявок, снова берутся под учёт: снятие клавишами, тейк, PANIC.
2. Заявки, завершившиеся без скрипта, учитываются через таблицу сделок. Частичные исполнения учитываются по каждой сделке.
3. Активные заявки SCLP, которых нет в файле, подхватываются с пометкой «подхвачена» и снимаются только вами (C). Свои заявки узнаются по диапазону TRANS_ID (1 800 000 000 – 1 809 999 999) или по метке `SCLP` в `brokerref`; метка есть у заявок фиксированного формата.
4. **Ручные и чужие заявки не трогаются никогда** — разве что `PANIC_KILL_SCOPE = "account"`.
5. Сделки своих заявок, номеров которых нет среди учтённых, проводятся через FIFO. Повторные OnTrade после переподключения отсекаются по номеру сделки.
6. Расчётная позиция сравнивается с `futures_client_holding.totalnet` (фондовый рынок: `depo_limits.currentbal` / лот). **При расхождении торговля блокируется.** В окне и отчёте два варианта:
   - **A, A** — принять позицию биржи: разница учитывается по средней цене брокера или по середине, без комиссии;
   - **P, P** — PANIC: закрыть позицию биржи целиком.
7. Тейк-профиты открытых ног, у которых пропала заявка, ставятся заново — пассивно, не больше позиции.
8. Всё перечисленное выводится в окно «SCLP: восстановление» и в журнал.

**Краевые случаи.**

- **Новый день.** Внутридневная статистика обнуляется, открытые ноги переносятся, журналы CSV остаются. Номера учтённых сделок **не** сбрасываются: торговый день FORTS начинается вечером предыдущей даты, и после ночного перезапуска вечерние сделки ещё лежат в таблице. Тест 15 ловил двойной учёт именно здесь.
- **Файла нет или он повреждён.** Восстановление идёт только по данным QUIK: сделки дня своих заявок по TRANS_ID и метке плюс сверка с позицией, в окне предупреждение. Ноги прошлых дней из сделок не восстановить — сверка покажет расхождение и предложит A,A или PANIC.
- **Инструмент истёк или в настройках сменился тикер.** При старте берётся **точный** прежний контракт (`inst_key`), а не заново вычисленный «ближайший». Если контракт больше недоступен, отчёт пишет, сколько ног и заявок осталось в его файле. Инструменты с открытыми ногами перечислены в отчёте («ВНИМАНИЕ: по … остались …»).
- **`CANCEL_ON_STOP = false`** (по умолчанию). При остановке заявки остаются в стакане и подхватываются при следующем запуске; в сообщении об остановке видно, сколько их. Хотите, чтобы остановка всё снимала, — `true`.

Что не восстанавливается: заявка, отправленная за миллисекунды до падения QUIK, если у неё нет ни номера в файле, ни TRANS_ID в таблице, ни метки. Её покажет сверка позиции или список чужих активных заявок.

### План ручной проверки восстановления (демо-счёт или 1 контракт)

1. **Активная заявка.** Поставьте покупку (↑) с отступом 0. Остановите скрипт в QUIK. Убедитесь в таблице заявок, что заявка стоит. Запустите SCLP. Отчёт: «заявка снова под управлением».
2. **Исполнение без скрипта.** Включите тейк (T). Поставьте покупку в лучший бид и остановите скрипт. Дождитесь исполнения — или исполните её встречной заявкой с другого счёта или руками. Запустите. Отчёт:
   - «исполнение без скрипта: покупка …»;
   - «позиция сходится с QUIK»;
   - «тейк-профиты открытых ног выставлены заново: 1».
3. **Частичное исполнение.** Повторите шаг 2 с объёмом 3: пусть без скрипта исполнится 1. После запуска у заявки «исполнено 1», нога одна на 1 лот, остаток заявки под управлением.
4. **Падение без сохранения.** Снимите задачу `info.exe` в диспетчере задач, пока стоят заявки и есть позиция. Запустите QUIK и SCLP: результат тот же, что в шагах 1–2.
5. **Ручная сделка.** При остановленном SCLP купите 1 контракт руками. Запуск: «РАСХОЖДЕНИЕ ПОЗИЦИИ», торговля заблокирована (↑ не работает). A, A → позиция принята. Повторите и выберите P, P → позиция закрыта.
6. **Повреждённый файл.** Откройте `sclp_state_….lua` и испортите текст. Запуск: «основной файл повреждён, взят резервный (.bak)». Испортите и `.bak`: «ФАЙЛ СОСТОЯНИЯ ПОВРЕЖДЁН», восстановление по данным QUIK.
7. **Переподключение.** Отключите QUIK от сервера и подключите снова, не останавливая скрипт. Позиция и счётчики не должны удвоиться: повторы OnTrade отсекаются по номеру сделки.
8. **Ручные заявки.** Поставьте руками заявку по тому же инструменту и перезапустите SCLP. Отчёт: «ручных/чужих активных заявок: 1 — SCLP их не трогает». C её не снимает.

## Ограничения

- Хоткеи работают только при фокусе на окне SCLP. Глобальные нужно делать через DLL — это вне QLua.
- В QLua нет функции звука. Сигнализация: `message()` (звук настраивается в QUIK: Настройки → Звуковое оповещение), подсветка строк, цветные ячейки.
- Нереализованный P&L считается по середине. Реальное закрытие PANIC будет хуже на половину спреда плюс проскальзывание.
- Окна клиринга и аукционов в `PAUSE_WINDOWS` заданы по расписанию MOEX, какое было известно. Сверьтесь с текущим.
